| checkpoint | 左后膝动作 std |
|---:|---:|
| 100 | 0.907 |
| 500 | 0.733 |
| 1000 | 0.993 |
| 2000 | 8.286 |
| 4700 | 291.568 |
| 9500 | 1951.465 |

9500 轮其余 11 个关节的 std 为 0.335–0.564。
Actor 最后输出层的左后膝权重行范数从第 500 轮的 0.558 增至 27.596，
其余输出行约 0.34–0.64，动作均值也已退化，并非只有探索噪声异常。

确定性回放中，该膝关节 **100%** 的原始动作越过 ±6；
采样回放中，gap/climb 的对应比例约 **99.95% / 99.975%**。
在临时限制 std 的回放中，该关节原始动作均值绝对值仍可超过 6700，
且未恢复正常行走。因此仅修改本 checkpoint 的 std 不足以修复策略。

平地对照中该关节的平均绝对施加力矩约 **21.4 N·m**，接近 23.5 N·m 的执行器饱和力矩。
动作裁剪到 ±6，再按 `q_target = -1.5 + 0.25 * action` 转换，
会产生 -3 或 0 rad 的膝目标；该关节硬范围约 [-2.72, -0.84] rad，两个目标均在范围外。
原始控制频繁饱和与膝关节高力矩、抖动同时出现。

## 代码机制与诊断边界

**2026-10-15 上游对照订正：** 原项目也只有 std 下限、保存裁剪前动作历史，
并截断总任务负奖励。这些属于共同行为，不能直接作为迁移独有缺陷或差距的根因。
真正已核实的偏差包括 std 与 log_std 参数化、AMP 优化/网络、世界模型损失尺度等，
详见 [UPSTREAM_PARITY.md](UPSTREAM_PARITY.md)。下面的回放事实保留，代码机制描述不等于已证明唯一诱因。

以下描述针对暂停的 v2 训练。v3 已恢复上游 std 参数化和主要学习语义，见
[修复验证](UPSTREAM_ALIGNMENT_RESULT.md)，不改变这里的历史回放结果。

1. v2 `learning/networks.py` 使用无界 Actor 均值与 `exp(log_std)`；
   `learning/ppo.py` 只限制 std 下限，并持续加入熵奖励，没有限制其上限。
   这允许有限但极大的均值/方差持续存在，当前的 NaN/Inf 检查无法识别该退化。
2. 环境在 `tasks/direct/wmp_env.py::_pre_physics_step` 中裁剪动作，
   动作变化惩罚及机器人执行看到的是裁剪结果；原始均值继续变大时，物理动作已处于饱和区。
   本次回放直接确认左后膝长期落在该区域。
3. `learning/runner.py` 的世界模型动作历史记录的是裁剪前采样动作，
   环境与策略观测中的上一动作则已裁剪，两者不一致。
   单膝出现数千量级原始动作时，世界模型收到的历史远超机器人实际执行范围。
4. 任务奖励最后整体 `clamp_min(0)`。回放中约 34–38% 的 gap/climb 步骤任务奖励为 0；
   在这些步骤里，不同程度的负奖励被合并，削弱了对坏动作严重程度的区分。
   新诊断脚本对完整奖励逐项分解，重建后与环境奖励数值一致。

前三项是直接核对得到的实现行为；动作均值/方差发散、饱和和基础步态退化已经实测。
熵项、动作历史不一致与奖励截断各自对训练退化的贡献，仍需修复后的训练消融来区分，
不能仅凭本次回放认定唯一的最初诱因。

课程判定方面，directional 地形要求沿 +x 前进超过 3 m 且横向误差小于 1 m。
回放的真实位移不足以触发升级，因此目前没有证据表明 gap/climb 等级为 0 是日志漏记。
早期 500 轮 checkpoint 的 std 较正常，但同样未通过基础行走/越障测试，不能称为已验证的恢复点。

## 后续修复建议

- 约束策略分布的均值/方差，并按关节范围约束位置目标，消除当前的长期饱和。
- 分开保存 PPO 原始采样动作与实际执行动作，世界模型历史使用与执行一致的动作；
  保持 PPO 的动作与 log probability 对应，避免直接替换后引入概率计算错误。
- 记录每关节 std、均值、裁剪率、位置目标越界率与实际课程进度；异常时及时保存并停止。
- 检查负奖励截断和前进奖励的组合，避免把抖动中的短时速度奖励误当成净前进。
- 修复后先验证稳定平地步态，再单独验证 gap/climb，最后恢复混合地形训练。
