## 结果

默认相机已改为 wmp_go1 的 WarpCam 和原版射线 kernel。Go2 资产没有更换或简化，
自碰撞保持开启。PD、奖励、课程、PPO/AMP、深度预测器和世界模型已重新对照有效上游配置。
本轮还修正训练入口的默认迭代上限：20000→100000，与上游一致；保存间隔仍为1000。
这只是配置修正，本轮所有运行都有固定步数、迭代数或超时上限。

模拟器实际确认 Go2 为19个刚体、27个碰撞形状、标称质量16.086998kg，
PhysX articulation 的 `enabledSelfCollisions` 为True。25个Go2资产文件逐字节与修改前备份一致。
新相机没有解决4100环境/1100相机的整体显存不足；2048/550通过完整批次短验证。

## 相机实现

- `sensors/upstream_wmp/warp_camera_kernels.py` 与固定参考文件逐字节一致；
  `warp_cam.py` 只调整相对导入，来源写入 `PROVENANCE.json`。
- 新 `WMPWarpDepthCamera` 将 IsaacLab 的机身wxyz转换为原核心使用的xyzw，
  把相机外参与机身姿态合成，所有相机共享同一参考地形网格。
  地形网格包含heightfield与附加障碍，坐标已扣除参考border偏移。
- 保留原整数像素坐标、64×64、58°水平视场、轴向深度、0–2m截断，
  归一化为[-0.5,0.5]。每5个控制步更新一次，10Hz；双帧缓存延迟一帧。
- 安装随机化在初始化时采样一次：XYZ±1cm，pitch15–25°，roll/yaw±2°。
- Go1安装点是base坐标(0.28,0,0.12)m；Go2保留原描述的前相机点
  (0.32715,-0.00003,0.04297)m，均叠加上述朝向和随机化。
- 渲染器的图像/姿态缓冲只按真实相机数分配。1100相机可见相机张量约17.25MiB，
  550相机约8.62MiB；不含Warp BVH、CUDA图和共享网格。
  环境为保持接口仍保存按全部环境分配的双帧深度，不声称全部相机相关张量都紧凑化。
- Isaac Sim内置Warp不能直接在外部Torch默认流上捕获原图，适配层使用自有Warp流、
  事件等待保证Torch位姿写入→渲染→Torch读取的顺序；原kernel数学定义未改。
- 保留旧SparseRay入口和RTX入口。play/diagnose读取checkpoint的相机实现；
  历史checkpoint缺少字段时选择旧SparseRay，新checkpoint记录wmp_go1。
  相机字段和源码哈希进入完整训练契约，旧实验不能静默切换相机续训。

原版 `WarpDepthCamera` 与新适配器在相同非对称场景、安装随机姿态和多帧机身运动下，
GPU逐像素对照通过。归一化最大绝对误差：
Go1=6.73532486e-06，
Go2=2.5331974e-06；对应米制深度约13.5和5.1微米。
小误差来自float32光学旋转合并及运算次序；本测试容差为归一化atol=2e-5、rtol=2e-5。
CUDA图捕获和后续重放均实际执行。

名义关节姿态保持上游：hip左右±0.1、前thigh0.8/后thigh1.0、calf−1.5rad。
显式PD先按逐关节限制裁剪，再乘每个物理子步的电机强度；不存在DC电机速度降额。
真实GPU验证直接调用原 `_compute_torques` 对照输出，并覆盖强度0.8/1/1.2和延迟0/1/2子步。

对完整有效配置做递归比较，76个叶字段差异仅来自机器人名称、USD路径、关节力矩/速度限制、
出生高度、安装位置，以及各地形配置中记录的tilt宽度。PAPER_CFG两机器人只差robot字段。
没有给Go2额外加入奖励倍率或缩小世界模型。

物理配置也已对照：TGS、位置4/速度0次迭代、contact offset0.01、rest offset0、
最大去穿透速度1m/s；Go1/Go2一致。随机化范围一致：摩擦0.5–2、恢复系数0、
base附加质量0–3kg、其他链接质量0.8–1.2倍、COM各轴±0.05m、
PD系数0.8–1.2倍（reset时）、电机强度0.8–1.2倍（物理子步）、
动作延迟0/1/2子步、每15s的XY速度推力±1m/s。

| 机体Z线速度平方 / 绊脚 | −1 / −1 |
| 脚边缘 / stuck / cheat / stool高度 | 各−1 |

跟踪sigma=0.25；特定障碍使用原速度裁剪；加速度用相邻控制帧dq差分；
脚腾空使用原两帧接触过滤；stumble为水平力>4×垂直力；stuck使用机身X速度与X指令；
stool只惩罚相对出生点高度>0.45m。逐项求和乘控制dt，再将总任务奖励截断至非负。
边缘课程在4000至10000迭代把倍率由0.1升至1。
测试实际提取原奖励函数，对Go1/Go2全部16个非零任务项及最终总奖励做数值对照并通过。

默认地形是参考17类及原比例、10行×20列、8m地块、0.1/0.005m分辨率、25m边界，
初始level0。地形升级/降级、命令课程、heading、reset/timeout和相机地形分配沿用前次已修正流程。
Go2只保留tilt宽度适配；梅花桩为显式扩展，默认比例不包含。

  完成一次PPO默认更新、50次depth更新和10次16×64的WM更新。

  为提前触发功能验证，使用ring回放与world_train_start=1；不把它当作默认完成episode回放的长训测试。
- Go2 4100/1100：仍OOM，发生于PPO rollout堆叠时申请194MiB；
  设备可用总量约11.47GiB，整个设备采样峰值约11.34GiB。
  报错时PyTorch已分配约1.78GiB，进程总占用约10.63GiB；两者差额包含PhysX/Kit/Warp等非Torch分配，
  不能将所有占用都归为相机。保留自碰撞和完整Go2资产时，当前已验证规模是2048/550。
