## 规模检查发现并修复的问题

开启原版自碰撞后，原PhysX默认容量在4100环境下不够：Go1触发碰撞栈溢出并丢弃接触，
Go2另外触发patch缓冲溢出。当前碰撞栈设为128MiB，patch容量设为1048576。
出现溢出的运行不计入通过结果，日志保留用于回溯。

4100路深度预测和图像编码还会产生较大的临时张量。当前无梯度感知推理每512环境一批，
RSSM仍按完整batch采样，训练batch、梯度、损失及网络定义保持一致。
实际深度预测器和世界模型编码器的整批/分批数值对照通过。

Go2的4100/1100配置在本机RTX5070的11.47GiB可用显存上仍发生OOM，
包括使用`PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True`的复测。
因此保留参考默认配置，并通过显式降低并行规模验证Go2；没有把4100的失败记成通过。

## 兼容与结论边界

新环境使用`go1_reference_v6`，控制版本为`upstream_pd_v1`。
旧资产和历史模型保留，但不能跨到新环境直接续训；新模型需从零建立参考实验。
即使v4契约一致，恢复也会重新reset和预热，大型回放、完整物理状态及全局RNG未保存，
不承诺逐帧重复。

这些检查证明修复后的数据、流程和短时更新可执行，不证明越障成功率或长训收敛。
Isaac Sim与Isaac Gym的PhysX版本、force sensor与ContactSensor信号仍有后端差异；
本轮没有运行Gym动力学基线，也没有实际ROS2/Gazebo或实机验证。
